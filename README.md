## Docker 部署与页面更新

3.6.1 起，更新口令 `GAME_REQ_UPDATE_TOKEN` 只需非空，支持中文、数字、符号和空格，不再要求 32 字符。要用短口令需先更换镜像（网页更新不会替换镜像自带的更新进程），并保留原端口及数据卷。未配置口令时，上传和重启接口关闭。请在 HTTPS 或可信内网使用更新页。

镜像已声明 `GAME_REQ_UPDATE_TOKEN`，默认留空。在部署面板的环境变量列表中填写该项即可，面板若隐藏镜像默认变量则手动添加同名项。页面的管理员口令填写相同的值。

- 构建：在项目根目录安装依赖后运行 `pnpm run build-only`，再运行 `node server/zip.js`。以当前 `package.json` 的版本生成两个更新包。
- 前端更新：上传 `server/dist.zip`，只更换前端，不重启服务。需要新后台接口时不要单独用此包。
- 服务端更新：上传 `server/release.zip`，包含前端、服务端模块、`package.json` 和 `pnpm-lock.yaml`。容器先用锁文件安装生产依赖，成功后切换并重启；应用未通过健康检查时恢复原版本。进度与结果显示在弹窗和首页日志。
- 页面更新适用于应用代码及容器内可安装的 Node 依赖。改变 Node、系统库、容器启动逻辑，或需要生命周期安装脚本的依赖时，使用新镜像。页面更新写入当前容器，替换容器前应将对应版本构建为镜像。
- `/opt/server/data/checkin` 要配置持久化挂载，更新不覆盖签到配置、日志和防重复记录。若旧服务用应用自带 HTTPS，将原证书文件只读挂载到独立目录并设置 `GAME_REQ_TLS_DIR`；不要把证书或静态资源目录挂到可替换的 `/opt/server/dist`。镜像和更新包均不包含私钥或登录凭据。

镜像构建后可在 Docker 主机运行 `python3 docker/smoke-update.py 镜像名`，验证两种更新包与失败回退。脚本只创建临时容器，不启用签到。


## 每日签到

首页“每日签到”进入站点列表 `/#/checkin`，点击“老王论坛”进入 `/#/checkin/laowang`。支持 Cookie 更新、固定时间或在指定时段内每日随机执行、代理、登录检查和执行记录。后台独立运行，不要求浏览器常开。

本地启动、Cookie 辅助插件和 Docker 持久化说明见 [每日签到说明](server/checkin/README.md)。
